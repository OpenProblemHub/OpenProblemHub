# OpenProblemHub

OpenProblemHub is a curated repository of real-world engineering problems.

It focuses on **problem quality**, not solution quantity.

This is not a place to share ideas.
It is a place to document precise, validated, constraint-aware problems
that deserve serious engineering attention.

---

## What This Repository Is

OpenProblemHub collects:

- Real-world problems experienced by engineers
- Clearly scoped and constraint-defined situations
- Problems validated by observable signals
- Issues that require non-trivial engineering judgment

Each accepted problem follows a strict template and review process.

---

## What This Repository Is Not

This repository is NOT:

- An idea dumping ground
- A startup brainstorming board
- A feature wishlist
- A marketing opportunity
- A solution showcase

Submissions that do not meet the quality bar will be rejected.

---

## Core Principles

1. Problem-first thinking
2. Real-world constraints over ideal scenarios
3. Validation over speculation
4. Precision over volume
5. Long-term signal integrity over short-term growth

---

---

## Submission Process

All problems must be submitted via Pull Request.

Steps:

1. Fork the repository
2. Create a new branch
3. Add a problem file under `problems/under-review/`
4. Use the official template
5. Open a Pull Request

Reviewers will evaluate submissions using the formal checklist.

Possible outcomes:

- Accept
- Revise
- Reject

---

## Quality Bar

To be accepted, a problem must:

- Describe a real, current situation
- Define a specific target user
- Acknowledge real-world constraints
- Provide validation signals
- Justify engineering relevance

Failure to meet any critical criteria results in rejection.

See `governance/review-checklist.md` for details.

---

## Who Should Contribute

Engineers who:

- Have experienced concrete technical pain
- Can articulate constraints clearly
- Value precision over hype
- Are willing to accept structured review

---

## Governance

OpenProblemHub operates under defined roles and decision rules.

- Review authority is earned, not automatic
- Disagreements default to stricter interpretation
- Quality protection overrides speed or popularity

See the `governance/` directory for full documentation.

---

## Why This Exists

Many repositories collect solutions.
Few curate high-quality problems.

Without well-defined problems,
engineering effort drifts toward noise.

OpenProblemHub exists to preserve problem clarity.
